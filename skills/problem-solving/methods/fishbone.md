# Fishbone Diagram (Ishikawa Diagram)

## 개요

**Fishbone Diagram**(또는 Ishikawa Diagram, 특성 요인도)은 문제의 잠재적 원인을
카테고리별로 시각화하는 분석 도구입니다. 생선 뼈 모양으로 원인-결과 관계를 표현합니다.

---

## 사용 시점

- 다중 원인이 의심될 때
- 팀 브레인스토밍 시
- 원인을 체계적으로 분류하고 싶을 때
- 문제의 전체 그림을 파악하고 싶을 때

---

## 6M 카테고리

소프트웨어 개발에 맞게 조정된 6M 카테고리:

### 1. Man (사람)
개발자, 운영자, 사용자 관련 요인

**예시**:
- 개발자 실수
- 지식/경험 부족
- 커뮤니케이션 오류
- 교육 부족
- 피로/주의 분산

### 2. Machine (기계/시스템)
서버, 인프라, 하드웨어 관련 요인

**예시**:
- 서버 리소스 부족
- 네트워크 불안정
- 하드웨어 장애
- 클라우드 서비스 문제
- 로드밸런서 오설정

### 3. Method (방법/프로세스)
개발 프로세스, 절차 관련 요인

**예시**:
- 코드 리뷰 누락
- 테스트 부족
- 배포 프로세스 오류
- 문서화 미흡
- 표준 미준수

### 4. Material (자재/데이터)
입력 데이터, 의존성 관련 요인

**예시**:
- 잘못된 입력 데이터
- 데이터 정합성 오류
- 외부 API 응답 오류
- 라이브러리 버그
- 의존성 버전 충돌

### 5. Measurement (측정/모니터링)
모니터링, 로깅, 알림 관련 요인

**예시**:
- 로깅 부족
- 모니터링 미흡
- 알림 설정 오류
- 메트릭 부재
- 테스트 커버리지 부족

### 6. Milieu (환경)
환경 설정, 외부 요인 관련

**예시**:
- 환경 변수 오류
- 개발/프로덕션 환경 차이
- 타임존 문제
- 외부 서비스 장애
- 보안 설정 문제

## 다이어그램 구조

```
                    ┌── Man (사람)
                    │   ├── 개발자 실수
                    │   └── 지식 부족
                    │
                    ├── Machine (기계)
                    │   ├── 서버 리소스
                    │   └── 네트워크
                    │
                    ├── Method (방법)
                    │   ├── 코드 리뷰 누락
                    │   └── 테스트 부족
{문제} ◄────────────┤
                    ├── Material (자재)
                    │   ├── 입력 데이터 오류
                    │   └── 의존성 버그
                    │
                    ├── Measurement (측정)
                    │   ├── 로깅 부족
                    │   └── 모니터링 미흡
                    │
                    └── Milieu (환경)
                        ├── 환경 변수 오류
                        └── 환경 차이
```

## 작성 프로세스

### Step 1: 문제 정의

오른쪽 끝에 문제를 명시합니다.

```
                                    ┌─────────────────┐
────────────────────────────────────┤ 로그인 API 실패 │
                                    └─────────────────┘
```

### Step 2: 주요 카테고리 추가

6M 카테고리를 뼈대로 추가합니다.

```
            Man ─────────────┐
                             │
         Machine ────────────┤
                             │
          Method ────────────┼──────── 문제
                             │
        Material ────────────┤
                             │
     Measurement ────────────┤
                             │
          Milieu ────────────┘
```

### Step 3: 원인 브레인스토밍

각 카테고리별로 가능한 원인을 나열합니다.

```
Man:
- 새 개발자가 API 스펙 이해 부족
- 코드 리뷰어가 누락된 부분 발견 못함

Machine:
- DB 서버 응답 지연
- 메모리 부족

Method:
- 통합 테스트 미실행
- 배포 전 체크리스트 누락

...
```

### Step 4: 근본 원인 식별

각 원인에 대해 5 Whys를 적용하여 근본 원인을 찾습니다.

```
Method: 통합 테스트 미실행
  → Why? CI/CD에 통합 테스트 단계 없음
  → Why? 파이프라인 설정 시 누락
  → Why? 체크리스트에 없음
  → 근본 원인: CI/CD 설정 체크리스트 미흡
```

### Step 5: 우선순위 결정

근본 원인들의 우선순위를 결정합니다.

```
우선순위:
1. CI/CD 설정 체크리스트 → 영향도 높음, 수정 쉬움
2. 코드 리뷰 프로세스 → 영향도 높음, 수정 중간
3. 개발자 교육 → 영향도 중간, 수정 어려움
```

## 예시: 로그인 API 500 에러

```
============================================
[SOLVE] Fishbone 분석: 로그인 API 500 에러
============================================

                    ┌── Man (사람)
                    │   ├── 신규 개발자 API 스펙 이해 부족
                    │   └── 코드 리뷰어 DB 쿼리 검증 누락
                    │
                    ├── Machine (기계)
                    │   ├── (해당 없음)
                    │   └──
                    │
                    ├── Method (방법)
                    │   ├── 마이그레이션 실행 누락 ⭐
                    │   ├── 통합 테스트 미실행
                    │   └── 배포 체크리스트 불완전
                    │
500 에러 ◄──────────┤
                    ├── Material (자재)
                    │   ├── DB 스키마 불일치 ⭐
                    │   └──
                    │
                    ├── Measurement (측정)
                    │   ├── DB 스키마 검증 없음
                    │   └── 배포 전 헬스체크 미흡
                    │
                    └── Milieu (환경)
                        ├── 스테이징 환경 누락
                        └──

⭐ = 핵심 원인

============================================
근본 원인 분석 결과:

1. Method: 마이그레이션 실행 누락
   → CI/CD에 마이그레이션 단계 없음
   → 해결: CI/CD 파이프라인에 마이그레이션 추가

2. Material: DB 스키마 불일치
   → 마이그레이션 미실행으로 인한 결과
   → 해결: 마이그레이션 실행

3. Measurement: DB 스키마 검증 없음
   → 배포 전 스키마 체크 없음
   → 해결: 스키마 검증 단계 추가

============================================
```

## 관련 방법론

- **5 Whys**: 각 원인의 근본 원인 추적
- **RCA**: 체계적 분석 프레임워크
- **브레인스토밍**: 원인 아이디어 수집
