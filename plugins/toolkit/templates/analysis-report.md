## 사용 목적

이 템플릿은 `/solve` 명령어의 분석 단계(Phase 3-4)에서 원인 분석 결과를 기록하기 위해 사용됩니다.

## 분석 방법론 가이드

### 5 Whys 적용 가이드

**언제 사용:**
- 단일 원인이 의심될 때
- 빠른 근본 원인 파악이 필요할 때
- 문제가 비교적 단순할 때

**주의점:**
- 5번에서 멈출 필요 없음 (3번이나 7번도 가능)
- 각 Why에 증거 필요
- 분기점 발견 시 모든 경로 탐색

### Fishbone 적용 가이드

**언제 사용:**
- 복합적 원인이 의심될 때
- 시스템적 문제일 때
- 팀 브레인스토밍 시

**6M 카테고리:**
- **Man**: 사람, 교육, 스킬
- **Machine**: 시스템, 도구, 인프라
- **Method**: 프로세스, 절차
- **Material**: 데이터, 입력, 의존성
- **Measurement**: 모니터링, 메트릭
- **Milieu**: 환경, 외부 요인

### Binary Search 적용 가이드

**언제 사용:**
- 코드의 어느 부분이 문제인지 모를 때
- 대량의 코드 변경 후 문제 발생 시
- 특정 커밋 이후 문제 발생 시

## 금지 사항

### 분석 시 하지 말아야 할 것

1. **5 Whys**
   - 증거 없이 "~인 것 같다"로 답변 금지
   - 첫 번째 답변에서 멈추지 않기
   - 개인 비난 (Blame)으로 끝나는 분석 금지

2. **가설 검증**
   - 확증 편향에 빠지지 않기
   - 반증 증거 무시 금지
   - 단일 가설만 고려 금지

3. **결론**
   - 근거 없는 결론 금지
   - "확실히"라고 단정하되 증거 없음 금지
   - 해결책 없이 분석만 하기 금지
