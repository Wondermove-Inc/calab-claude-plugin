## 사용 목적

이 템플릿은 `/solve` 명령어 실행 시 문제를 체계적으로 정의하기 위해 사용됩니다.

## 작성 가이드

### 심각도 기준

| 심각도 | 기준 | 대응 시간 | 예시 |
|--------|------|----------|------|
| 🔥 **Critical** | 서비스 전체 중단, 데이터 손실 위험 | 즉시 | 전체 장애, DB 손상 |
| 🔴 **High** | 핵심 기능 장애, 다수 사용자 영향 | 4시간 내 | 결제 불가, 로그인 실패 |
| 🟡 **Medium** | 일부 기능 장애, 우회 가능 | 24시간 내 | 검색 오류, UI 깨짐 |
| 🟢 **Low** | 사소한 문제, 사용에 큰 영향 없음 | 1주 내 | 오타, 미세한 UI 이슈 |

### 좋은 문제 정의 예시

```markdown
## 1. 증상 (Symptom)

### 1.1 무엇이 발생했는가?

**관찰된 현상:**
로그인 페이지에서 유효한 이메일/비밀번호 입력 후 로그인 버튼 클릭 시
500 Internal Server Error 응답을 받으며 로그인이 되지 않음.

**기대 동작:**
올바른 자격 증명 입력 시 200 OK와 함께 JWT 토큰을 받고 대시보드로 리다이렉트

**실제 동작:**
500 Internal Server Error 응답, 에러 페이지 표시, 사용자 로그인 불가

**증상 확인 방법:**
```bash
curl -X POST https://api.example.com/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"test@example.com","password":"password123"}'
# Response: 500 Internal Server Error
```

### 1.2 언제 발생했는가?

| 항목 | 내용 |
|------|------|
| **최초 발생** | 2024-01-15 09:45 KST |
| **발생 빈도** | 100% (모든 로그인 시도) |
| **발생 패턴** | v2.1.0 배포 직후부터 지속 |
| **발생 트리거** | 로그인 버튼 클릭 |
```

## 금지 사항

### 문제 정의 시 하지 말아야 할 것

1. **증상 기술**
   - 추측을 사실처럼 기술 금지
   - "~인 것 같다" 대신 관찰된 사실만 기술
   - 에러 메시지 요약 대신 전문 복사

2. **재현 조건**
   - "가끔 발생"처럼 모호한 표현 금지
   - 구체적인 재현 단계 없이 "알아서 재현됨" 금지
   - 환경 정보 누락 금지

3. **가설**
   - 증거 없이 단정 금지
   - "확실히 A가 원인"보다 "A일 가능성 높음" 사용
   - 가설 하나만 세우고 확증 편향에 빠지지 않기

4. **일반적 실수**
   - 문제와 해결책 혼동 금지 (문제 정의에 집중)
   - 개인 의견을 팀 결론처럼 표현 금지
   - 비난보다 사실에 집중 (Blameless)
