# /handoff-replica - 세션 간 컨텍스트 동기화

> **현재 세션의 맥락을 빠짐없이 문서화 → 새 세션이 읽고 동일 컨텍스트로 복원**

기존 `/handoff`(Opus→Codex 구현 위임)와 다릅니다. 이건 **같은 모델의 세션→세션**
컨텍스트 이어받기 전용입니다. 모델 간 위임이 아니라 "이어달리기 바통"입니다.

## 사용법

```bash
/handoff-replica [작업명]              # 현재 세션 → 핸드오프 문서 작성 (쓰기 모드)
/handoff-replica --resume <문서경로>   # 핸드오프 문서 읽고 컨텍스트 복원 (읽기 모드)
```

## 트리거 키워드

`핸드오프`, `세션 인계`, `컨텍스트 동기화`, `이어받기`, `바통`, `replica`

## 모드 1: 쓰기 (핸드오프 문서 작성)

> 현재 세션을 종료하기 전, 다음 세션이 막힘없이 이어갈 수 있도록 문서를 만듭니다.

### 작성 원칙 (절대 준수)

1. **분량 제한 없음** — 이번 세션/작업에서 중요한 내용은 **모두 꼼꼼하게 빠짐없이** 기록.
   단, 길기만 하면 핵심을 못 찾으므로 **맨 위에 TL;DR 3~5줄 요약**을 반드시 둔다 (요약 + 상세 병행).
2. **사고 과정까지 기록** — 결과물뿐 아니라 *왜 그렇게 했는지*를 남겨야 진짜 컨텍스트가 이어진다.
3. **절대경로** — 모든 파일/디렉토리는 절대경로로 작성하여 새 세션의 혼동을 제거.
4. **외부 추측 금지** — 모르는 건 "미확인"으로 표기. 없는 티켓/문서/경로를 지어내지 않는다.

### 작성 항목 (`templates/replica-template.md` 기반)

| # | 섹션 | 내용 |
|---|------|------|
| 0 | **TL;DR** | 3~5줄. 지금 뭐 하고 있고, 어디까지 했고, 새 세션이 제일 먼저 할 일 |
| 1 | **목적 / 배경 / 주요 업무** | 이 작업을 왜 하는지, 어떤 맥락에서 시작됐는지, 핵심 업무 항목 |
| 2 | **Phase 진행 상황** | 지나온 phase(작업+결과), 현재 진행 중 phase, 앞으로 수행할 phase |
| 3 | **결정 사항 + 이유 (Decision Log)** | 채택한 방식 + 버린 대안 + 그 이유. 새 세션의 방향 되돌이 방지 |
| 4 | **시행착오 / 막다른 길** | 이미 시도했다 실패한 것. 같은 삽질 반복 방지 |
| 5 | **현재 상태 스냅샷** | git 브랜치, 미커밋 변경, 열린 PR, 실행 중 프로세스, 주요 환경값 |
| 6 | **바로 다음 액션 (1~2개)** | 새 세션이 *제일 먼저* 해야 할 구체적 한두 가지 (phase와 별개) |
| 7 | **관련 파일 (절대경로 + 한 줄 설명)** | 경로만이 아니라 *왜 중요한지*까지 |
| 8 | **JIRA / Confluence** | 관련 티켓 키·제목·작성정보, Confluence 문서 링크. 누락 금지 |
| 9 | **로드맵** | 작업 관련 로드맵 요약 + 로드맵 파일 절대경로(있으면) |
| 10 | **제약 / 주의사항** | 건드리면 안 되는 것, 함정, 프로젝트 규칙(예: 배포 금지, 특정 소스 수정 금지) |
| 11 | **검증 방법** | 작업이 제대로 됐는지 확인하는 명령/쿼리/테스트 (검증된 것만) |
| 12 | **미해결 질문 / 블로커** | 아직 결정 못 한 것, 사용자에게 물어봐야 할 것 |

### 실행 절차

1. **컨텍스트 수집**
   - 현재 세션 대화 흐름에서 목적/결정/시행착오 파악
   - `git status`, `git branch --show-current`, `git log --oneline -10` 으로 상태 스냅샷
   - 관련 메모리 파일(`.claude/memory/CURRENT_CONTEXT.md` 등) 참조
   - JIRA/Confluence/로드맵 정보는 **세션에 언급된 것만** 수집 (없으면 "없음"으로 명시)

2. **문서 생성**
   - 템플릿 기반으로 위 13개 섹션 작성
   - **저장 위치**: `<프로젝트 루트>/.claude/handoff/replica-{YYYYMMDD-HHMM}-{작업slug}.md` (절대경로)

3. **자기 검증** (작성 후 확인)
   - [ ] 새 세션이 이 문서만 읽고 작업을 이어갈 수 있는가?
   - [ ] TL;DR만 읽어도 전체 그림이 잡히는가?
   - [ ] 모든 경로가 절대경로인가?
   - [ ] 결정의 *이유*가 들어있는가? (결과만 나열 ❌)
   - [ ] 지어낸 정보(없는 티켓/경로)는 없는가?

4. **사용자 확인**
   ```
   ============================================
    HANDOFF-REPLICA 문서 생성 완료
   ============================================

    📄 파일: /Users/smlee/.../​.claude/handoff/replica-20260522-1430-{작업}.md

    📋 요약:
    • 작업: [한 줄]
    • 현재 phase: [N/M]
    • 다음 액션: [한 줄]

    ▶ 새 세션에서 복원:
    /handoff-replica --resume /Users/smlee/.../replica-20260522-1430-{작업}.md

   ============================================
   ```

## 모드 2: 읽기 (--resume, 컨텍스트 복원)

> 새 세션 시작 직후, 핸드오프 문서를 읽어 이전 세션의 맥락을 그대로 흡수합니다.

> **🚫 CRITICAL — 절대 바로 작업을 시작하지 마라.**
> 핸드오프 문서를 읽으면 곧장 "다음 액션"을 실행해버리는 경우가 많다.
> 반드시 **자신이 파악한 상황을 먼저 정리해서 보고하고, 사용자 승인을 기다린 뒤** 작업한다.
> 이는 (1) 컨텍스트를 제대로 이해했는지 사용자가 검증하고, (2) 문서 작성 이후 바뀐
> 상황을 사용자가 보정할 기회를 주기 위함이다. 보고 전 어떤 파일 수정·명령 실행도 금지.

### 실행 절차

1. **문서 읽기** — 지정된 절대경로의 replica 문서 전체를 Read
2. **상태 동기화 확인** — 문서의 "현재 상태 스냅샷"과 실제 환경을 대조
   - `git branch --show-current`, `git status`로 브랜치/변경사항 일치 확인
   - 불일치 시 사용자에게 경고 (문서 작성 이후 상태가 바뀌었을 수 있음)
3. **파악한 상황 정리 보고 (필수, 작업 시작 전)** — 문서를 그대로 복붙하지 말고,
   *자신이 이해한 내용을 자기 말로* 재구성해서 보고한다. 이해도가 드러나야 검증이 된다.
   ```
   ============================================
    컨텍스트 복원 — 제가 파악한 상황입니다
   ============================================
    • 작업 목적/배경: [자기 말로 요약]
    • 지금까지 진행: phase [N/M] — [핵심 결과]
    • 핵심 결정과 이유: [왜 이렇게 됐는지 자기 말로]
    • 현재 상태: [브랜치/변경사항] (상태 일치: ✅ / ⚠️)
    • 제가 이해한 "다음 할 일": [바로 다음 액션]
    • 주의/제약: [건드리면 안 되는 것]
    • 불명확하거나 확인이 필요한 점: [있으면 질문]

    ▶ 위 이해가 맞는지 확인해 주세요. 승인하시면 다음 액션부터 진행하겠습니다.
   ============================================
   ```
4. **사용자 승인 대기** — 사용자가 "맞다 / 진행해라"라고 확정하기 **전에는 작업을 시작하지 않는다.**
   사용자가 보정·추가 지시를 주면 반영한 뒤, 명시적 승인을 받고 "다음 액션"부터 진행한다.
