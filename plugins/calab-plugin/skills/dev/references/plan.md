# /dev --plan - 기획 단계

> **브레인스토밍 + PRD 작성**

## 실행 옵션

```bash
/dev --plan [기능명]           # 전체 기획 (브레인스토밍 + PRD)
/dev --plan --brainstorm       # 브레인스토밍만
/dev --plan --prd              # PRD만 (브레인스토밍 필요)
```

---

## Phase 1: 브레인스토밍 (`--brainstorm`)

### Step 1: 기능 폴더 생성

```bash
.claude/docs/active/{feature-name}/
└── 01-brainstorm.md
```

### Step 2: 아이디어 체계화

**01-brainstorm.md 작성:**

```markdown
# 브레인스토밍: {기능명}

## 1. 문제 정의
### 현재 상황
- {현재 어떤 문제가 있는가}

### 핵심 문제
- {해결해야 할 근본 문제}

### 영향
- {이 문제가 미치는 영향}

---

## 2. 목표 사용자
| 구분 | 설명 |
|------|------|
| 주요 사용자 | {누가 사용하는가} |
| 사용 맥락 | {언제/어디서} |
| 기대 가치 | {무엇을 얻는가} |

---

## 3. 핵심 가치 제안
> **한 문장 요약**: {이 기능이 제공하는 핵심 가치}

---

## 4. 기능 범위
### In Scope (포함)
- [ ] {구현할 기능 1}
- [ ] {구현할 기능 2}

### Out of Scope (제외)
- {이번에 구현하지 않을 것}

---

## 5. 성공 지표
| 지표 | 목표 | 측정 방법 |
|------|------|----------|
| {지표1} | {목표값} | {측정법} |

---

## 6. 리스크 & 고려사항
- **기술적**: {기술 리스크}
- **비즈니스**: {비즈니스 리스크}
- **의존성**: {외부 의존성}
```

### Step 3: 리서치 통합 (선택)

`/research` 결과가 있다면:
```
.claude/research/{topic}/report.md 참조하여 통합
```

---

## Phase 2: PRD 작성 (`--prd`)

### Step 1: 브레인스토밍 로드

```
.claude/docs/active/{feature-name}/01-brainstorm.md 읽기
```

- **부차 목표**: {추가 목표}

### 1.3 성공 지표 (KPI)

- 페인포인트: {현재 불편함}

## 3. 기능 요구사항

### 3.1 P0 (필수)
| ID | 요구사항 | 수용 기준 |
|----|----------|----------|

| ID | 요구사항 | 수용 기준 |

### 3.3 P2 (선택)
| ID | 요구사항 | 수용 기준 |

---

## 4. 비기능 요구사항

- 응답 시간: {목표}
- 처리량: {목표}

### 4.2 보안
- {보안 요구사항}

### 4.3 확장성
- {확장성 요구사항}

## 5. 제약 사항

- **일정 제약**: {제약}
- **리소스 제약**: {제약}

## 6. 가정 및 의존성
- **가정**: {전제 조건}
- **의존성**: {외부 의존성}

## 7. 마일스톤
| 단계 | 내용 | 목표일 |

| M1 | {내용} | {날짜} |

## 8. 참조
- 브레인스토밍: 01-brainstorm.md
- 리서치: .claude/research/{topic}/
