# /brainstorm - 발산적 사고 + 원인 분석

> **탐색하고 구체화하는 단계. 결론이 나오면 /plan으로 이어갑니다.**

## 사용법

```bash
/brainstorm [주제]                    # 아이디어 발산 + 구체화
/brainstorm [에러 상황]               # 원인 분석 + 가설 도출
/brainstorm --5whys [에러 상황]       # 5 Whys 기법으로 근본 원인 추적
/brainstorm --rca [에러 상황]         # Root Cause Analysis (복잡한 장애)
/brainstorm --hypothesis [에러 상황]  # 가설 기반 검증 (다중 원인)
```

## 활용 시나리오

| 상황 | 입력 예시 | 산출물 | 다음 단계 |
|------|----------|--------|----------|
| 기능 아이디어 | "사용자 알림 시스템" | 접근 방식 + 트레이드오프 | → `/plan` |
| 에러 분석 | "간헐적 504 타임아웃" | 원인 후보 + 검증 방법 | → `/plan` (수정 계획) |
| 설계 고민 | "캐싱 전략 선택" | 옵션 비교 + 권장안 | → `/plan --design` |
| 작업 구체화 | "성능 개선" | 구체적 개선 포인트 | → `/plan` |
| 반복 장애 | "--rca 배포 후 OOM" | 근본 원인 + 재발 방지책 | → `/plan` |

## 분석 기법 (에러/장애 분석 시)

| 기법 | 옵션 | 적합한 상황 | 참조 |
|------|------|------------|------|
| 5 Whys | `--5whys` | 원인이 불명확, 빠르게 추적 | `references/5whys.md` |
| RCA | `--rca` | 복잡한 장애, 다중 원인, post-mortem | `references/rca.md` |
| 가설 검증 | `--hypothesis` | 원인 후보 여러 개, 실험으로 확인 | `references/hypothesis.md` |
| 자유 분석 | (옵션 없음) | 가벼운 탐색, 아이디어 정리 | — |

### 기법 자동 선택 (옵션 미지정 시)

| 상황 | 자동 선택 |
|------|----------|
| 스택트레이스 있는 에러 | 5 Whys |
| 간헐적/복잡한 장애 | RCA |
| "왜 이럴까?" 류 질문 | 가설 검증 |
| 기능/설계 관련 | 자유 분석 (기법 미적용) |

## 진행 방식

### 1단계: 맥락 파악 (자동)

```
- 프로젝트 컨텍스트 확인 (.claude/project-context/)
- 관련 코드/설정 탐색 (Explore 에이전트)
- 에러 분석 시: root-cause-finder 에이전트 호출
- 필요 시 웹 검색 (web-researcher)
```

### 2단계: 발산 — 가능성 나열

에러 분석인 경우:
```markdown
## 원인 후보

| # | 가설 | 근거 | 가능성 | 검증 방법 |
|---|------|------|--------|----------|
| 1 | DB 커넥션 풀 고갈 | 동시 요청 증가 시 발생 | 높음 | 커넥션 수 모니터링 |
| 2 | 외부 API 응답 지연 | 타임아웃 로그 패턴 | 중간 | API 응답시간 확인 |
| 3 | 메모리 누수 | 장시간 운영 후 발생 | 낮음 | 메모리 프로파일링 |
```

아이디어 구체화인 경우:
```markdown
## 접근 방식

| # | 방안 | 장점 | 단점 | 복잡도 |
|---|------|------|------|--------|
| 1 | WebSocket 실시간 알림 | 즉시 전달 | 인프라 복잡 | 높음 |
| 2 | SSE + 폴링 하이브리드 | 구현 단순 | 지연 있음 | 중간 |
| 3 | 푸시 알림 서비스 연동 | 모바일 지원 | 외부 의존 | 중간 |
```

### 3단계: 수렴 — 방향 제시

```markdown
## 결론

**권장**: 방안 2 (SSE + 폴링 하이브리드)
- 이유: 현재 인프라에 적합, 구현 2일 이내 가능
- 리스크: 대규모 사용자 시 폴링 부하
- 대안: 방안 1 (규모 확장 필요 시)
```

### 4단계: 다음 단계 안내

| brainstorm 결과 | 권장 다음 단계 |
|----------------|---------------|
| 기능 아이디어 구체화됨 | `/plan` (PRD 작성) |
| 에러 원인 파악됨 | `/plan` (수정 계획 → Codex 위임) |
| 설계 방향 결정됨 | `/plan --design` (설계 포함) |
| 추가 조사 필요 | `/research` (심층 리서치) |

## 적응적 스킵

| 상황 | 실행 흐름 | 스킵 |
|------|----------|------|
| 복잡한 장애 | 맥락 파악 → 분석(RCA) → 수렴 → 안내 | 없음 |
| 명확한 에러 | 분석(5whys) → 수렴 → 안내 | 맥락 파악 스킵 |
| 가벼운 아이디어 | 발산 → 수렴 → 안내 | 분석 기법 스킵 |
| 단순 질문 | 바로 답변 | 전체 스킵 |

---

## 산출물 규칙

- 별도 파일 생성 **하지 않음** (대화 내에서 완결)
- 표 형식으로 구조화하여 비교 가능하게 제시
- 결론에 **권장안 1개** 명시
- 분석 기법 사용 시 해당 기법의 구조를 따라 출력
