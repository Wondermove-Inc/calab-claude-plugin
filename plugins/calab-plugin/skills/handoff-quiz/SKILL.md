# /handoff-quiz - 세션 컨텍스트 인계 검증 퀴즈

> **`/handoff-replica`의 검증 짝꿍.** 새 세션이 컨텍스트를 *진짜로* 이어받았는지 퀴즈로 확인.

## 워크플로우

```
[기존 세션] /handoff-replica       → 핸드오프 문서 작성
[기존 세션] /handoff-quiz          → 주관식 20문제 출제 (정답은 기존 세션이 보유)
       ↓ 문제만 새 세션에 전달
[새 세션]   문제 풀이              → 흡수한 컨텍스트로 답변 작성
       ↓ 답변을 기존 세션에 붙여넣기
[기존 세션] /handoff-quiz --grade  → 정답 대조 → 유지율 점수 + 손실 영역 진단
```

## 사용법

```bash
/handoff-quiz                 # 주관식 20문제 출제 (기본)
/handoff-quiz --count 10      # 문항 수 조절 (기본 20)
/handoff-quiz --grade         # 새 세션 답변을 붙여넣고 채점
```

## 트리거 키워드

`핸드오프 퀴즈`, `컨텍스트 검증`, `인계 확인`, `퀴즈 출제`, `퀴즈 채점`, `quiz`

## 모드 1: 출제 (기본)

> **기존 세션**이 자신의 실제 작업 맥락을 바탕으로 주관식 문제를 만든다.

### 출제 원칙 (절대 준수)

1. **일반 지식으로 못 푸는 문제만** — "REST가 뭐냐" 같은 보편 지식 ❌.
   *"이 세션에서 A 대신 B를 택한 이유는?"* 처럼 **이 세션 고유의 맥락**을 알아야만
   풀 수 있는 문제여야 검증 의미가 있다.
2. **전부 주관식** — O·X·객관식 금지. 서술형으로만.
3. **컨텍스트 영역 골고루 커버** — 아래 분배표를 따른다 (handoff-replica 13개 섹션 대응).
4. **난이도 혼합** — 표면 사실(경로/티켓번호/브랜치) + 깊은 맥락(결정 이유/피해야 할 것)을 섞는다.
5. **정답을 함께 보관** — 출제 시 각 문항의 **모범답안**을 내부적으로 작성해 둔다 (채점 기준).

### 영역별 문항 분배 (기본 20문항 기준)

| 영역 | 문항 수 | 예시 질문 유형 |
|------|:------:|---------------|
| 목적 / 배경 | 2 | 이 작업을 시작하게 된 근본 이유는? |
| Phase 진행 상황 | 2 | 현재 어느 phase이며, 직전 phase의 결과는? |
| 결정 사항 + 이유 | 4 | X 방식을 채택하고 Y를 버린 이유는? |
| 시행착오 / 막다른 길 | 2 | 이미 시도했다 실패한 접근과 그 원인은? |
| 현재 상태 스냅샷 | 2 | 현재 작업 브랜치와 미커밋 변경 상태는? |
| 다음 액션 | 2 | 새 세션이 가장 먼저 해야 할 구체적 작업은? |
| 관련 파일 (절대경로) | 2 | 핵심 파일 경로와 그 역할은? |
| JIRA / Confluence / 로드맵 | 2 | 관련 티켓 키와 그 내용은? |
| 제약 / 주의 / 블로커 | 2 | 이 작업에서 절대 건드리면 안 되는 것은? |

> `--count N`이면 비율을 유지한 채 문항 수를 조정. 결정 이유 영역은 항상 최다 비중 유지
> (컨텍스트 인계 실패가 가장 잘 드러나는 영역이므로).

### 출제 절차

1. **컨텍스트 수집** — 현재 세션 대화 흐름 + 작성된 handoff-replica 문서(있으면) + git 상태
2. **20문항 생성** — 위 분배표에 따라 주관식 문제 작성
3. **모범답안 작성** — 각 문항의 정답을 내부 보관 (채점 시 사용)
4. **출력** — 문제만 번호 매겨 출력 (정답은 노출하지 않음)

```
============================================
 HANDOFF QUIZ — 컨텍스트 인계 검증 (20문항, 주관식)
============================================
 ▶ 아래 문제를 새 세션에 전달하세요.
   새 세션의 답변을 받아 `/handoff-quiz --grade`로 채점합니다.

 Q1. ...
 Q2. ...
 ...
 Q20. ...
============================================
```

> **정답 보관**: 모범답안은 `<프로젝트 루트>/.claude/handoff/quiz-{YYYYMMDD-HHMM}.md`에
> 저장(절대경로). 채점 시 참조.

## 모드 2: 채점 (--grade)

> **기존 세션**이 새 세션의 답변을 받아 모범답안과 대조한다.

### 채점 절차

1. **답변 수집** — 사용자가 붙여넣은 새 세션 답변을 문항별로 파싱
2. **대조** — 각 답변을 보관된 모범답안과 비교
   - **정답**: 핵심 내용 일치
   - **부분 정답**: 방향은 맞으나 핵심 일부 누락
   - **오답**: 틀리거나 맥락에 없는 내용
3. **정량 + 정성 리포트**

```
============================================
 HANDOFF QUIZ 채점 결과
============================================
 컨텍스트 유지율: 17/20 (85%)  [정답 15 · 부분 2 · 오답 3]

 영역별 점수:
 ✅ 목적/배경         2/2
 ✅ Phase 진행        2/2
 ⚠️ 결정 사항+이유    2/4   ← 손실 영역
 ✅ 시행착오          2/2
 ...

 ❌ 틀린 문항:
 • Q7 (결정 이유): [요약] — 새 세션이 채택 이유를 반대로 이해
 • Q12 (제약): [요약] — 배포 금지 규칙 누락

 📌 진단: "결정 이유" 영역 인계 실패.
    → handoff-replica 문서의 Decision Log 보강 권장.
============================================
```

### 판정 가이드

| 유지율 | 판정 | 권장 조치 |
|--------|------|----------|
| 90%+ | 인계 성공 | 작업 이어서 진행 |
| 70~89% | 부분 인계 | 손실 영역만 보강 후 재확인 |
| ~69% | 인계 실패 | handoff-replica 문서 대폭 보강 → 새 세션 재시작 |
