# /jira-ticket - JIRA 티켓 추천

> **작업 계획을 JIRA 티켓으로 변환. 제목 + 내용 + Sub-task 추천.**

## 사용법

```bash
/jira-ticket [작업명]              # 현재 컨텍스트 기반 티켓 추천
/jira-ticket [PRD 파일 경로]       # PRD 기반 티켓 추천
/jira-ticket --subtasks            # Sub-task 포함 추천
```

## 워크플로우 위치

```
brainstorm → research → plan → /jira-ticket → (JIRA 생성) → handoff
```

---

## 실행 절차

### Step 1: 컨텍스트 수집

다음 순서로 작업 맥락을 파악합니다:

1. **인자로 PRD 경로가 주어진 경우** → 해당 PRD 파일 읽기
2. **작업명만 주어진 경우** → `.claude/docs/active/` 에서 관련 PRD 검색
3. **인자 없는 경우** → `.claude/memory/CURRENT_CONTEXT.md`에서 최근 작업 확인

수집 대상:
- PRD (요구사항, AC, 구현 방향)
- 브레인스토밍 결과 (있으면)
- 리서치 결과 (있으면)

### Step 2: 메인 티켓 생성

아래 형식으로 메인 JIRA 티켓을 추천합니다:

```
============================================
 JIRA 티켓 추천
============================================

[메인 티켓]

  제목: [동사형 시작, 핵심 기능 명시]
  유형: Story / Task / Bug

  --- 내용 ---
  ## 목적
  [이 작업을 왜 하는지 1-2문장]

  ## 배경
  [현재 상황, 문제점, 필요성 2-3문장]

  ## 주요 업무
  - [ ] [구체적 작업 항목 1]
  - [ ] [구체적 작업 항목 2]
  - [ ] [구체적 작업 항목 3]

  ## 완료 조건 (AC)
  - [검증 가능한 조건 1]
  - [검증 가능한 조건 2]
  ---

============================================
```

### Step 3: Sub-task 생성 (선택)

`--subtasks` 옵션이 있거나, 메인 티켓의 주요 업무가 3개 이상이면 Sub-task를 추천합니다.

Sub-task 규칙:
- **최대 5개** — 너무 많으면 관리 부담
- **최소 2개** — 1개면 Sub-task 불필요
- 각 Sub-task는 **독립적으로 완료 가능**한 단위
- 제목은 메인 티켓과 연결되도록 작성

```
[Sub-task 1/N]

  제목: [메인 티켓 맥락 + 구체적 작업]
  유형: Sub-task

  --- 내용 ---
  ## 목적
  [1문장]

  ## 주요 업무
  - [ ] [작업 항목]

  ## 완료 조건
  - [조건]
  ---
```

### Step 4: 사용자 확인

추천 결과를 보여주고 수정 여부를 확인합니다.

---

## 제목 작성 규칙

| 규칙 | 좋은 예 | 나쁜 예 |
|------|---------|---------|
| 동사형 시작 | "사용자 알림 시스템 구현" | "알림 시스템" |
| 구체적 범위 | "ClickHouse S3 티어링 설정 추가" | "스토리지 개선" |
| 측정 가능 | "로그인 API 응답시간 2초→500ms 개선" | "성능 개선" |
| 간결 | 30자 이내 권장 | 장황한 설명 |

## 내용 작성 규칙

- **목적**: "왜" 하는지 (비즈니스 가치 중심)
- **배경**: "현재 상황"과 "문제점" (기술 맥락)
- **주요 업무**: 체크박스 형태, 구체적 행동 동사 사용
- **완료 조건**: PRD의 AC에서 가져오되, JIRA에 맞게 간결하게

## Sub-task 분할 기준

| 기준 | 분할 O | 분할 X |
|------|--------|--------|
| 작업 시간 | 4시간 이상 예상 | 2시간 이내 |
| 담당자 | 다른 사람이 할 수 있음 | 같은 사람이 연속 수행 |
| 독립성 | 병렬 진행 가능 | 순차 의존 (A→B→C) |
| 검증 | 별도 테스트 가능 | 통합 테스트만 가능 |

## 예시

### 입력
```
/jira-ticket ClickHouse S3 스토리지 티어링 --subtasks
```

### 출력
```
============================================
 JIRA 티켓 추천
============================================

[메인 티켓]

  제목: ClickHouse S3 스토리지 티어링 구현
  유형: Story

  --- 내용 ---
  ## 목적
  ClickHouse 데이터를 Hot/Warm/Cold 3티어로 자동 분류하여
  스토리지 비용을 절감한다.

  ## 배경
  현재 모든 데이터가 EBS에 저장되어 스토리지 비용이 월 $X 발생.
  7일 이후 데이터는 조회 빈도가 낮아 S3로 이동 가능.

  ## 주요 업무
  - [ ] S3 버킷 및 IAM 정책 설정
  - [ ] ClickHouse storage policy 설정 (default/s3 2볼륨)
  - [ ] TTL MOVE 규칙 적용 (7일 기준)
  - [ ] Glacier IR 아카이브 파이프라인 구축
  - [ ] 운영 모니터링 대시보드 구성

  ## 완료 조건
  - 7일 경과 데이터가 S3로 자동 이동됨
  - S3 데이터 쿼리 응답시간 3초 이내
  - Glacier 아카이브 자동 실행 확인
  ---

[Sub-task 1/3]

  제목: S3 스토리지 연동 및 storage policy 설정
  유형: Sub-task

  --- 내용 ---
  ## 목적
  ClickHouse가 S3를 볼륨으로 사용할 수 있도록 설정한다.

  ## 주요 업무
  - [ ] S3 버킷 생성 + IAM Role/Policy
  - [ ] storage.xml에 s3 디스크 및 볼륨 추가
  - [ ] 연결 테스트 (INSERT + SELECT)

  ## 완료 조건
  - S3 볼륨에 데이터 쓰기/읽기 정상 동작
  ---

[Sub-task 2/3]

  제목: TTL MOVE 규칙 적용 및 검증
  유형: Sub-task
  ...

[Sub-task 3/3]

  제목: Glacier IR 아카이브 파이프라인 구축
  유형: Sub-task
  ...

============================================
```
