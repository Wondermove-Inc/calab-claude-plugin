# /cleanup - PR 머지 후 브랜치 정리

> **PR 머지 완료 후 브랜치 정리 + dev 동기화를 안전하게 수행합니다.**

## 사용법

```bash
/cleanup                    # 현재 브랜치 기준 정리 + dev 동기화
/cleanup [브랜치명]          # 특정 브랜치 지정 정리
/cleanup --dry-run          # 실제 실행 없이 수행할 작업만 미리보기
```

## 워크플로우 위치

```
feature 브랜치 작업 → 커밋/푸시 → PR 생성 → PR 머지 → /cleanup
```

---

## 실행 절차

### Step 1: 사전 검증 (모두 통과해야 진행)

아래 검증을 **순서대로** 수행합니다. **하나라도 실패하면 즉시 중단**합니다.

```
┌─────────────────────────────────────────────────────────────┐
│  안전 검증 체크리스트 (하나라도 실패 시 중단)                   │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  □ 1. Git 저장소 확인                                       │
│     - git repo인지 확인                                     │
│     - 실패 시: "Git 저장소가 아닙니다" → 중단                │
│                                                             │
│  □ 2. 대상 브랜치 결정                                      │
│     - 인자로 브랜치명 지정 → 해당 브랜치                    │
│     - 인자 없음 → 현재 브랜치                               │
│     - 대상이 dev/main/master면 → "보호 브랜치는              │
│       정리 대상이 아닙니다" → 중단                          │
│                                                             │
│  □ 3. 미커밋 변경사항 확인                                  │
│     - git status로 staged/unstaged/untracked 확인           │
│     - 변경사항 있으면 → "커밋되지 않은 변경사항이 있습니다.   │
│       먼저 커밋하거나 stash하세요" → 중단                   │
│                                                             │
│  □ 4. PR 머지 여부 확인                                     │
│     - gh pr view [브랜치] --json state,mergedAt 실행        │
│     - state가 "MERGED"가 아니면:                            │
│       - "OPEN" → "PR이 아직 머지되지 않았습니다" → 중단     │
│       - "CLOSED" → "PR이 머지 없이 닫혔습니다.              │
│         정말 브랜치를 삭제하시겠습니까?" → 사용자 확인       │
│       - PR 없음 → "이 브랜치에 연결된 PR이 없습니다.        │
│         정말 브랜치를 삭제하시겠습니까?" → 사용자 확인       │
│                                                             │
│  □ 5. 원격 브랜치 존재 확인                                 │
│     - git ls-remote --heads origin [브랜치] 실행            │
│     - 없으면 → 원격 삭제 스킵 (이미 삭제됨)                │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### Step 2: 실행 계획 표시 + 사용자 확인

**반드시** 실행 전에 수행할 작업을 보여주고 사용자 확인을 받습니다.

```
============================================
 CLEANUP 실행 계획
============================================

 대상 브랜치: feat/SKPO-1234-user-auth
 PR 상태: MERGED (2026-03-13T04:30:00Z)
 베이스 브랜치: dev

 수행할 작업:
  1. git checkout dev
  2. git branch -d feat/SKPO-1234-user-auth  (로컬 삭제)
  3. git push origin --delete feat/SKPO-1234-user-auth  (원격 삭제)
  4. git pull origin dev  (최신화)

 진행하시겠습니까? (y/n)
============================================
```

`--dry-run` 옵션인 경우 여기서 종료합니다.

### Step 3: 실행

사용자가 확인하면 **순서대로** 실행합니다:

1. **dev checkout**
   ```bash
   git checkout dev
   ```
   - 실패 시 → 중단, 에러 메시지 표시

2. **로컬 브랜치 삭제** (`-d` 사용, `-D` 아님)
   ```bash
   git branch -d [브랜치명]
   ```
   - `-d`는 머지된 브랜치만 삭제 (안전)
   - 실패 시 → "브랜치가 완전히 머지되지 않았습니다" 경고
   - 사용자에게 `-D` (강제 삭제) 여부 확인

3. **원격 브랜치 삭제**
   ```bash
   git push origin --delete [브랜치명]
   ```
   - 이미 삭제됐으면 스킵
   - 실패 시 → 경고 표시 (진행은 계속)

4. **dev 최신화**
   ```bash
   git pull origin dev
   ```
   - 충돌 시 → 경고 표시

### Step 4: 결과 요약

```
============================================
 CLEANUP 완료
============================================

 ✅ dev checkout 완료
 ✅ 로컬 브랜치 삭제: feat/SKPO-1234-user-auth
 ✅ 원격 브랜치 삭제: feat/SKPO-1234-user-auth
 ✅ dev 최신화 완료 (3 commits pulled)

 현재 브랜치: dev
 최신 커밋: abc1234 "Merge PR #42: 사용자 인증 구현"
============================================
```

## 안전 규칙 (절대 준수)

| 규칙 | 설명 |
|------|------|
| **보호 브랜치 삭제 금지** | dev, main, master, release/* 는 절대 삭제 불가 |
| **`-d` 우선 사용** | `-D` (강제 삭제)는 사용자 명시적 확인 후에만 |
| **미커밋 변경 시 중단** | stash/commit 먼저 요구 |
| **PR 미머지 시 중단** | PR이 MERGED 상태여야 진행 |
| **사용자 확인 필수** | 실행 계획 표시 후 반드시 확인 |
| **`--dry-run` 지원** | 실제 실행 없이 계획만 확인 가능 |
| **`--force` 옵션 없음** | 안전장치를 우회하는 옵션은 제공하지 않음 |

## 에러 처리

| 상황 | 대응 |
|------|------|
| git checkout 실패 | 중단, 현재 상태 유지 |
| 로컬 삭제 실패 (-d) | 사용자에게 -D 여부 확인 |
| 원격 삭제 실패 | 경고 후 계속 (이미 삭제된 경우 등) |
| pull 충돌 | 경고 표시, 수동 해결 안내 |
| gh CLI 없음 | PR 확인 스킵, 사용자에게 머지 여부 직접 확인 |

## 예시

### 기본 사용
```
/cleanup
```
→ 현재 브랜치(feat/SKPO-1234)를 정리하고 dev로 복귀

### 특정 브랜치 정리
```
/cleanup feat/SKPO-5678-payment
```
→ 지정 브랜치를 정리 (현재 브랜치가 아니어도 가능)

### 미리보기
```
/cleanup --dry-run
```
→ 실제 실행 없이 수행할 작업만 확인
