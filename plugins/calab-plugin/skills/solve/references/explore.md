# 탐색 단계 (Exploration Phase)

## 개요

문제 해결의 첫 단계로, 문제와 관련된 코드베이스를 체계적으로 탐색합니다.
추측이 아닌 **실제 코드 확인**에 기반하여 문제의 범위와 영향을 파악합니다.

---

## 사용 시점

- 문제의 원인 위치가 불확실할 때
- 에러 메시지만으로 원인을 특정할 수 없을 때
- 코드베이스에 대한 이해가 부족할 때
- 문제가 여러 모듈에 걸쳐 있을 수 있을 때

---

## 4단계 탐색 프로세스

### Step 1: 에러 추적 (Error Tracing)

에러 메시지, 스택 트레이스에서 시작하여 발생 지점을 특정합니다.

```
입력: 에러 메시지 / 스택 트레이스
동작:
  1. 에러 발생 파일과 라인 번호 확인
  2. 해당 파일 읽기 (Read)
  3. 에러 발생 함수의 호출자 추적
출력: 에러 발생 위치 목록
```

### Step 2: 의존성 매핑 (Dependency Mapping)

에러 발생 지점에서 연관된 모듈과 파일을 파악합니다.

```
입력: 에러 발생 위치
동작:
  1. import / require 관계 추적
  2. 공유 상태 (state, context) 확인
  3. 설정 파일 의존성 확인
출력: 영향받는 파일/모듈 목록
```

### Step 3: 변경 이력 확인 (Change History)

최근 변경 사항이 문제의 원인인지 확인합니다.

```
입력: 관련 파일 목록
동작:
  1. git log로 최근 변경 확인
  2. git diff로 변경 내용 파악
  3. 변경 시점과 문제 발생 시점 대조
출력: 의심 변경 목록
```

### Step 4: 재현 조건 파악 (Reproduction Conditions)

문제를 재현할 수 있는 조건을 정리합니다.

```
입력: 탐색 결과
동작:
  1. 필수 조건 (환경, 데이터, 순서) 정리
  2. 최소 재현 시나리오 구성
  3. 재현 가능 여부 확인
출력: 재현 조건 문서
```

---

## 탐색 결과 형식

탐색 완료 후 다음 형식으로 결과를 정리합니다:

```markdown
## 탐색 결과

### 에러 위치
- 파일: `src/path/to/file.ts:123`
- 함수: `functionName()`
- 에러: `TypeError: Cannot read property 'x' of undefined`

### 영향 범위
- 직접 영향: 3개 파일
- 간접 영향: 5개 파일

### 의심 원인
1. [가능성 높음] 최근 변경된 X 모듈
2. [가능성 중간] Y 설정 값 변경
3. [가능성 낮음] Z 라이브러리 버전

### 재현 조건
- 환경: production
- 조건: 사용자가 A 후 B를 수행할 때
```

## 탐색 에이전트 호출

```python
Task(
    subagent_type="Explore",
    description="문제 관련 코드 탐색",
    prompt="""
    다음 문제에 관련된 코드를 탐색하세요:

    [문제 설명]

    탐색 범위:
    1. 에러 발생 파일 및 관련 import 추적
    2. 최근 변경 이력 (git log)
    3. 관련 설정 파일
    4. 테스트 파일

    결과를 위치, 영향 범위, 의심 원인 형식으로 정리하세요.
    """
)
```

## 주의사항

| 규칙 | 설명 |
|------|------|
| **코드 먼저 읽기** | 추측 금지. 반드시 파일을 읽고 확인 |
| **범위 제한** | 무한 탐색 방지. 관련성 높은 파일 위주 |
| **기록 남기기** | 탐색한 파일과 발견 사항을 모두 기록 |
| **수정 금지** | 탐색 단계에서는 코드 수정 하지 않음 |
