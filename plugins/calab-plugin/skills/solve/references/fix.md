# 수정 단계 (Fix Phase)

## 개요

근본 원인 분석이 완료된 후, TDD 워크플로우에 따라 버그를 수정합니다.
**테스트 먼저, 수정 후, 검증** 순서를 반드시 따릅니다.

---

## 사용 시점

- 근본 원인이 파악된 후
- root-cause-finder 에이전트의 분석 결과가 있을 때
- 수정 범위와 영향이 명확할 때

---

## TDD 기반 수정 프로세스

### Step 1: 실패 테스트 작성 (Red)

버그를 재현하는 테스트를 먼저 작성합니다.

```
입력: 근본 원인 분석 결과
동작:
  1. 버그를 정확히 재현하는 테스트 케이스 작성
  2. 엣지 케이스 테스트 추가
  3. 테스트 실행 → 실패 확인 (Red 상태)
출력: 실패하는 테스트 파일
```

### Step 2: 최소 수정 (Green)

테스트를 통과하는 최소한의 수정을 적용합니다.

```
입력: 실패 테스트 + 근본 원인
동작:
  1. 근본 원인에 대한 최소 수정 코드 작성
  2. 테스트 실행 → 통과 확인 (Green 상태)
  3. 기존 테스트 전체 실행 → 회귀 없음 확인
출력: 수정된 소스 코드
```

### Step 3: 리팩토링 (Refactor)

수정 코드의 품질을 개선합니다.

```
입력: Green 상태 코드
동작:
  1. 코드 중복 제거
  2. 변수/함수 이름 개선
  3. 주석 추가
  4. 테스트 재실행 → 여전히 Green 확인
출력: 리팩토링된 코드
```

### Step 4: 회귀 테스트 (Regression)

수정이 다른 기능에 영향을 주지 않는지 확인합니다.

```
입력: 수정된 코드
동작:
  1. 전체 테스트 스위트 실행
  2. 린트 체크
  3. 빌드 확인
출력: 전체 테스트 통과 확인
```

### Step 5: 문서화

수정 내용과 원인을 기록합니다.

```
입력: 수정 결과
동작:
  1. fix-report.md 작성
  2. knowledge-base에 패턴 등록
출력: .claude/problem-solving/resolved/{id}/fix-report.md
```

## 수정 보고서 형식

```markdown
## 버그 수정 보고서

### 근본 원인
[분석 결과 요약]

### 수정 내용
| 파일 | 변경 | 이유 |
|------|------|------|
| `src/path/file.ts` | X 조건 추가 | null 체크 누락 |

### 테스트
- 추가된 테스트: 3개
- 전체 테스트 통과: ✅
- 회귀 없음: ✅

### 방지 대책
[재발 방지를 위한 제안]
```

## bug-fixer 에이전트 호출

```python
Task(
    subagent_type="calab-plugin:bug-fixer",
    description="TDD 기반 버그 수정",
    prompt="""
    다음 근본 원인 분석을 기반으로 버그를 수정하세요:

    [근본 원인 분석 결과]

    TDD 프로세스:
    1. 버그를 재현하는 실패 테스트 작성
    2. 최소 수정으로 테스트 통과
    3. 리팩토링
    4. 회귀 테스트 전체 실행

    산출물: .claude/problem-solving/resolved/{id}/fix-report.md
    """
)
```

## 수정 원칙

| 원칙 | 설명 |
|------|------|
| **최소 수정** | 근본 원인만 수정. 주변 코드 리팩토링은 별도 작업 |
| **테스트 우선** | 수정 전 반드시 실패 테스트 작성 |
| **회귀 방지** | 전체 테스트 통과 필수 |
| **문서화** | 수정 내용과 원인을 반드시 기록 |
| **패턴 등록** | 유사 문제 재발 방지를 위해 knowledge-base에 등록 |

---

## 자동 수정 vs 확인 필요

| 자동 수정 가능 | 사용자 확인 필요 |
|---------------|-----------------|
| 타입 오류 수정 | 비즈니스 로직 변경 |
| null 체크 추가 | API 인터페이스 변경 |
| import 수정 | 데이터 스키마 변경 |
| 누락된 에러 처리 | 성능 트레이드오프 |
