# TDD 워크플로우 가이드

> Simple Worker 에이전트가 참조합니다.

## 핵심 규칙

**모든 코드 로직 변경 작업은 TDD로 실행합니다.**

| 규칙 | 위반 시 처리 |
|------|------------|
| 구현 전 테스트 작성 필수 | RED 먼저 수행 |
| RED 상태를 검증해야 함 | RED 미확인 시 오케스트레이터에 보고 |
| GREEN 상태를 검증해야 함 | GREEN 미확인 시 오케스트레이터에 보고 |
| 테스트 없이 구현 코드 작성 금지 | 즉시 중단, 오케스트레이터에 보고 |

## TDD 사이클

```
RED:      실패하는 테스트 작성 → 실행 → FAIL 확인
GREEN:    테스트 통과하는 최소 코드 작성 → 실행 → PASS 확인
REFACTOR: 코드 개선 (선택) → 실행 → PASS 유지
```

## 절대 금지

- 구현(GREEN)을 테스트(RED) 이전에 수행
- 테스트 없이 구현 코드 작성
- 테스트 실패 확인 없이 구현 진행

## TDD 스킵 허용 케이스

> 코드 로직 변경이 없는 경우에만 스킵 허용

| 스킵 허용 | 예시 |
|-----------|------|
| 설정 파일 수정 | config.yaml, .env |
| 문서 수정 | README.md, CHANGELOG.md |
| 단순 오타 수정 | 주석 오타, 로그 메시지 오타 |
| 테스트 불가능 코드 | main 함수, CLI 진입점 |

| 스킵 불가 (TDD 필수) | 예시 |
|---------------------|------|
| 버그 수정 | 로직 오류, 예외 처리 누락 |
| 새 기능 구현 | 함수/메서드/클래스 추가 |
| 리팩토링 | 함수 분리, 인터페이스 변경 |
| API 변경 | 엔드포인트, 파라미터 변경 |

## 테스트 실패 핸들링

| 단계 | PASS 시 | FAIL 시 |
|------|---------|---------|
| RED | 테스트 잘못됨 → 수정 | 정상 → GREEN 진행 |
| GREEN | 성공 → REFACTOR 진행 | 코드 수정 → 재실행 (최대 3회) |
| REFACTOR | 성공 | 리팩토링 롤백 |

GREEN 3회 연속 실패 시 오케스트레이터에 보고합니다.
