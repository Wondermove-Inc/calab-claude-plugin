# Testing Rules

> **테스트 관련 필수 규칙 - 항상 준수**

## 커버리지 요구사항

| 커버리지 | 최소 | 권장 | 차단 기준 |
|---------|------|------|----------|
| 라인 | 70% | 80% | 70% 미만 |
| 브랜치 | 60% | 70% | 50% 미만 |
| 함수 | 80% | 90% | 70% 미만 |

## 필수 규칙

### 1. 테스트 작성 의무

- 새로운 함수/클래스 → 단위 테스트 필수
- 새로운 API 엔드포인트 → 통합 테스트 필수
- 버그 수정 → 회귀 테스트 필수

### 2. 테스트 명명

```
should [동작] when [조건]
```

### 3. 테스트 구조

```typescript
// AAA 패턴 또는 Given-When-Then
it('should ...', () => {
  // Arrange / Given
  // Act / When
  // Assert / Then
});
```

### 4. 금지 사항

- ❌ 프로덕션 코드에서 테스트 코드 의존
- ❌ 테스트에서 실제 외부 서비스 호출
- ❌ 테스트 간 상태 공유
- ❌ 하드코딩된 타임아웃 (flaky test 원인)

### 5. TDD 강제 상황

`--tdd` 옵션 사용 시:
1. 테스트 먼저 작성 (Red)
2. 최소 구현 (Green)
3. 리팩토링 (Refactor)

## 자동 검사

PR/커밋 시 자동 확인:
- [ ] 커버리지 임계값 충족
- [ ] 모든 테스트 통과
- [ ] 새 코드에 테스트 존재
