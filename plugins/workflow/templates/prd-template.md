## 작성 가이드

### PRD 작성 원칙

1. **사용자 중심**: 모든 요구사항은 사용자 가치와 연결
2. **측정 가능**: 성공 기준은 측정 가능하게
3. **MVP 집중**: 핵심 기능에 집중, 범위 확장 방지
4. **살아있는 문서**: 정기적으로 업데이트

### 체크리스트

- [ ] 문제 정의가 명확한가?
- [ ] 성공 지표가 측정 가능한가?
- [ ] MVP 범위가 명확한가?
- [ ] 비목표가 명시되어 있는가?
- [ ] 모든 가정이 나열되어 있는가?
- [ ] 주요 리스크가 식별되어 있는가?
- [ ] 이해관계자 승인을 받았는가?

### 금지 사항

- ❌ 모호한 요구사항 (예: "빠르게", "쉽게")
- ❌ 측정 불가능한 성공 기준
- ❌ 기술 구현 세부사항 포함 (별도 TDD에서 다룸)
- ❌ 너무 많은 기능을 한 번에 포함
- ❌ 검증되지 않은 가정을 사실로 기술
