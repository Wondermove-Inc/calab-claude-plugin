# 리네이밍 치환 체크리스트

> Worker/Team Worker가 용어/식별자 리네이밍 작업 시 참조합니다.
> 단순 `sed`/`grep -r`로 일괄 치환하면 본문 외 위치가 누락되기 쉽습니다.

## 점검 대상 5개 영역

리네이밍 후 아래 5개 영역을 **각각 별도 grep**으로 검증합니다.

| # | 영역 | 누락되기 쉬운 이유 | 점검 방법 |
|---|------|-------------------|----------|
| 1 | **YAML frontmatter** (`name`, `description`) | `---` 블록은 본문 grep 패턴에서 제외되는 경우 많음 | `grep -n "^name:\|^description:" *.md` |
| 2 | **섹션 헤딩** (`#`, `##`, `###`) | 헤딩은 구조 토큰으로 인식되어 치환 스킵되기도 함 | `grep -nE "^#+ .*<옛이름>" *.md` |
| 3 | **코드 블록 내부 식별자** | 펜스 안의 문자열은 의도적으로 보존하는 경우가 있어 일괄 치환 시 건너뛰기 쉬움 | 펜스 내부까지 포함해 grep |
| 4 | **템플릿 문자열** (SendMessage 본문, 메시지 템플릿 등) | 따옴표로 감싸진 멀티라인 문자열은 패턴이 길어져 놓치기 쉬움 | 관련 키워드(`SendMessage`, `message:`) 주변 재확인 |
| 5 | **한국어 조사 정합성** | 리네이밍으로 앞/뒤 단어의 **종성(받침)**이 바뀌면 조사도 바뀌어야 함 | `이/가`, `을/를`, `과/와`, `은/는` 재검토 |

## 최종 검증 루틴

```bash
# 1. 옛 이름 잔존 여부 전수 조사
grep -rn "<옛이름>" <대상 디렉토리>

# 2. 결과가 0건이어야 PR/커밋 진행
#    0건이 아니면 각 위치에서 위 5개 영역 중 어디에 해당하는지 식별 후 수정
```

## 조사 치환 예시

> 아래는 **조사 검증 원칙의 예시**일 뿐이며, 실제 현재 네이밍과 무관한 가상의 리네이밍 사례입니다.

| 옛 이름 | 새 이름 | 조사 변경 |
|---------|---------|----------|
| `캡틴` (종성 無) | `팀 리더` (종성 有) | `캡틴이` → `팀 리더가` |
| `worker` | `구현자` | `worker가` → `구현자가` |
| `manager` | `매니저` | `manager가` → `매니저가` (그대로) |

> **원칙**: 종성 유/무가 바뀌면 반드시 조사를 재검토합니다.
