# /docs update - 앱 문서 유지보수

> `docs/{앱이름}/` 에 생성된 기존 문서를 대상으로 **추가, 수정, 삭제, 검증**을 수행합니다.

## 전제 조건

- `/docs generate` 로 최초 문서가 이미 생성되어 있어야 합니다
- 대상 문서는 `docs/{앱이름}/` 폴더에 존재해야 합니다

## 문서의 목적 (generate 스킬과 동일)

모든 문서 변경은 다음 두 독자를 위해 수행됩니다:

1. **사람** — 앱의 전체 구조, 비즈니스 로직, API 스펙을 빠르게 파악
2. **AI** — 코드 변경/수정 시 기존 로직, 의존 관계, 사이드 이펙트를 정확히 이해하고 안전하게 작업

## 핵심 원칙

- **예시 코드 금지**: 핵심 로직과 규칙만 서술
- **Mermaid 시각화 필수**: 복잡한 개념은 반드시 Mermaid 다이어그램으로 시각화 (layout: elk)
- **변경 영향도 명시**: 주요 컴포넌트/로직마다 변경 시 영향 범위를 기술
- **구현 의도 기록**: "무엇을 하는가"가 아닌 "왜 이렇게 했는가"를 기록
- **generate 스킬의 문서별 작성 지침 준수**: 각 문서 파일의 필수 포함 항목과 필수 다이어그램 규칙을 따름

---

## 작업 유형

### 1. 추가 (Add)

기존 문서에 새로운 내용을 추가하거나, 새로운 문서 파일을 생성합니다.

**사용 상황:**
- 새로운 API 엔드포인트가 추가되어 api-specification.md에 반영 필요
- 새로운 이벤트가 추가되어 event-specification.md에 반영 필요
- 새로운 비즈니스 규칙이 추가되어 business-logic.md에 반영 필요
- 새로운 DB 컬렉션/테이블이 추가되어 database.md에 반영 필요

**실행 단계:**

```
1. 대상 앱의 docs/{앱이름}/ 폴더 확인
2. 추가할 내용과 관련된 코드 분석
3. 해당 문서 파일에 내용 추가
   - generate 스킬의 문서별 작성 지침에 따라 작성
   - 기존 문서의 구조와 스타일에 맞춰 일관성 유지
4. 추가된 내용이 다른 문서에 영향을 주는 경우 연관 문서도 함께 업데이트
5. 검증 수행
```

---

### 2. 수정 (Update)

코드 변경사항을 반영하여 기존 문서 내용을 수정합니다.

**사용 상황:**
- API 엔드포인트의 파라미터/응답이 변경됨
- 비즈니스 로직이 변경됨
- DB 스키마가 변경됨
- 아키텍처 패턴이 변경됨
- 기술 스택이 변경됨

**실행 단계:**

```
1. 변경 사항 파악
   ├── 사용자가 직접 변경 범위를 지정한 경우 → 해당 범위 분석
   └── 전체 스캔 요청인 경우 → git diff 또는 코드 분석으로 변경 감지
2. 변경된 코드와 관련된 문서 파일 식별
3. 해당 문서의 관련 섹션 수정
   - 변경된 내용만 정확히 반영 (불필요한 전체 재작성 금지)
   - 변경으로 인한 영향 범위 업데이트
4. 연쇄 영향 확인 및 반영
   - 해당 변경이 다른 문서에도 영향을 주는지 확인
   - 예: API 파라미터 변경 → api-specification.md + business-logic.md 모두 수정
5. 검증 수행
```

**변경 감지 매핑:**

| 변경된 코드 영역 | 영향받는 문서 |
|-----------------|-------------|
| 라우터/핸들러 | api-specification.md |
| 이벤트 발행/구독 | event-specification.md |
| 모델/스키마 정의 | database.md |
| 인덱스 정의 | database.md |
| 서비스/유스케이스 로직 | business-logic.md |
| 패키지 구조/의존성 | architecture.md |
| 미들웨어/인터셉터 | architecture.md |
| 외부 라이브러리 추가/제거 | tech-stack.md |
| 디렉토리 구조 변경 | overview.md, architecture.md |

---

### 3. 삭제 (Delete)

코드에서 제거된 기능/엔드포인트/이벤트 등에 대한 문서 내용을 제거합니다.

**사용 상황:**
- API 엔드포인트가 제거됨
- 이벤트가 제거됨
- DB 컬렉션/테이블이 제거됨
- 비즈니스 규칙이 폐기됨

**실행 단계:**

```
1. 삭제 대상 확인
2. 해당 문서에서 관련 내용 제거
3. 삭제된 항목을 참조하는 다른 문서의 내용도 정리
   - 다이어그램에서 해당 노드/흐름 제거
   - 요약 테이블에서 해당 행 제거
   - 관련 설명에서 참조 제거
4. 검증 수행
```

---

### 4. 검증 (Validate)

문서의 품질, 일관성, 완성도를 검증합니다.

**검증 항목:**

```
[검증 항목]
├── 구조 검증
│   ├── generate 스킬의 필수 포함 항목 충족 여부
│   ├── 필수 다이어그램 포함 여부
│   └── 필수 문서 파일 존재 여부 (선택 문서는 해당 시스템이 있을 때만)
├── 코드-문서 동기화 검증
│   ├── 문서에 기술된 API가 실제 코드에 존재하는지
│   ├── 문서에 기술된 이벤트가 실제 코드에 존재하는지
│   ├── 문서에 기술된 DB 스키마가 실제 코드와 일치하는지
│   └── 코드에 존재하지만 문서에 누락된 항목이 있는지
├── 일관성 검증
│   ├── 용어 통일 (동일한 개념에 다른 용어 사용 여부)
│   ├── 문서 간 상호 참조 정합성
│   └── 다이어그램과 본문 내용 일치 여부
├── 원칙 준수 검증
│   ├── 예시 코드 미포함 확인
│   ├── "왜" 관점의 설명 포함 여부 (설계 의도, 선택 이유)
│   ├── 변경 영향도/주의사항 기술 여부
│   └── 불변 규칙(invariants) 명시 여부
└── Mermaid 다이어그램 검증
    ├── 가독성 규칙 준수 (색상 대비)
    └── layout: elk 사용 여부 (flowchart의 경우)
```

**검증 결과 출력 형식:**

```
[검증 결과]

문서: docs/{앱이름}/
검증 대상: N개 파일

✅ 통과 항목
  - overview.md: 필수 항목 충족, 다이어그램 포함
  - architecture.md: 필수 항목 충족, 다이어그램 포함
  ...

❌ 오류 (반드시 수정)
  - api-specification.md: POST /api/orders 엔드포인트 누락 (코드에 존재)
  - database.md: orders 컬렉션의 status 필드 타입 불일치 (문서: string, 코드: enum)

⚠️ 경고 (권장 수정)
  - business-logic.md: 주문 취소 로직에 변경 영향도 미기술
  - event-specification.md: order.cancelled 이벤트의 멱등성 처리 방식 미기술
```

## Mermaid 다이어그램 규칙

generate 스킬과 동일한 규칙을 적용합니다:

**가독성 규칙 (필수 준수):**
- 어두운 배경 → 밝은 글자 (#ffffff, #fef3c7, #e0f2fe)
- 밝은 배경 → 어두운 글자 (#1e293b, #166534, #92400e)

**권장 스타일:**
```mermaid
%%{init: {'theme': 'base', 'themeVariables': {
  'primaryColor': '#4f46e5',
  'primaryTextColor': '#ffffff',
  'secondaryColor': '#f0fdf4',
  'tertiaryColor': '#fef3c7'
}}}%%
```

## 문서 구조 참조

update 스킬이 다루는 문서 구조는 generate 스킬에서 정의한 것과 동일합니다:

```
docs/{앱이름}/
├── overview.md                    # 앱 개요 및 빠른 이해 가이드
├── architecture.md                # 아키텍처, 패턴, 의존성 규칙
├── api-specification.md           # API 명세서
├── event-specification.md         # 이벤트 명세서
├── database.md                    # DB 스키마, 인덱스, 데이터 흐름
├── business-logic.md              # 비즈니스 로직 및 도메인 규칙
└── tech-stack.md                  # 기술 스택 설명
```

각 문서의 필수 포함 항목과 필수 다이어그램은 **generate 스킬의 문서별 작성 지침**을 참조합니다.

---

## 주의사항

> 문서 수정 시 기존 내용의 맥락을 훼손하지 않도록 주의합니다. 변경된 부분만 정확히 수정하고, 관련 없는 섹션은 건드리지 않습니다.

> 연쇄 영향을 반드시 확인합니다. 하나의 변경이 여러 문서에 걸쳐 영향을 줄 수 있습니다.

> 코드에 없는 내용을 추측하여 작성하지 않습니다. 실제 코드 분석 결과만 반영합니다.
