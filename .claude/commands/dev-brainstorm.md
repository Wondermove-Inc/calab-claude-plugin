# 브레인스토밍

## 목적

아이디어를 체계적으로 확장하고 구체화하여 개발 가능한 요구사항으로 변환합니다.

## 실행 절차

### Step 1: 아이디어 수집

$ARGUMENTS에서 아이디어를 파악하거나 사용자에게 질문:

```
무엇을 만들고 싶으신가요?
```

### Step 2: 브레인스토밍 진행

다음 질문들을 통해 아이디어 구체화:

#### 2.1 문제 정의

```
Q1. 어떤 문제를 해결하려고 하나요?
Q2. 현재 이 문제는 어떻게 해결되고 있나요?
Q3. 현재 솔루션의 문제점은 무엇인가요?
```

#### 2.2 타겟 사용자

```
Q4. 이 기능을 누가 사용하나요?
Q5. 사용자의 주요 니즈는 무엇인가요?
Q6. 사용자가 기대하는 경험은?
```

#### 2.3 핵심 가치

```
Q7. 이 기능의 핵심 가치는 무엇인가요?
Q8. 경쟁 제품과의 차별점은?
Q9. 왜 사용자가 이 기능을 선택해야 하나요?
```

#### 2.4 범위 정의

```
Q10. 반드시 포함해야 할 기능은? (Must-have)
Q11. 있으면 좋은 기능은? (Nice-to-have)
Q12. 이번에 포함하지 않을 기능은? (Out of scope)
```

### Step 3: 브레인스토밍 문서 작성

`docs/prd/{feature-name}/brainstorm.md` 작성:

```markdown

**작성일**: {날짜}

---

## 1. 아이디어 요약

{한 문장으로 요약}

---

## 2. 문제 정의

### 해결할 문제
{문제 설명}

### 현재 상황
{현재 해결 방법과 문제점}

---

## 3. 타겟 사용자

### 주요 사용자
| 페르소나 | 설명 | 니즈 |
|---------|------|------|
| {페르소나1} | {설명} | {니즈} |

### 사용자 여정
{사용자가 이 기능을 사용하는 시나리오}

---

## 4. 핵심 가치

### Value Proposition
{핵심 가치 제안}

### 차별화 포인트
- {차별화 1}
- {차별화 2}

---

## 5. 범위 정의

### Must-have (필수)
- [ ] {기능 1}
- [ ] {기능 2}

### Nice-to-have (선택)
- [ ] {기능 3}

### Out of Scope (제외)
- {제외 항목 1}

---

## 6. 초기 아이디어

### 기술적 접근
{기술적 구현 아이디어}

### 디자인 아이디어
{UX/UI 아이디어}

---

## 7. 리스크 및 고려사항

| 리스크 | 영향도 | 대응 방안 |
|--------|--------|----------|
| {리스크} | 높음/중간/낮음 | {대응} |

---

*다음 단계: /dev-prd*
```

### Step 4: 상태 업데이트

`.claude/memory/CURRENT_CONTEXT.md` 업데이트

```
• 타겟: {타겟 사용자}

 다음 단계: /dev-prd

============================================
```
