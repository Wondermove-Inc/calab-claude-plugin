# Binary Search Debugging

## 개요

**Binary Search Debugging**은 이분 탐색 알고리즘을 디버깅에 적용한 기법입니다.
코드나 변경 이력을 절반씩 나누어 문제 범위를 빠르게 좁혀나갑니다.

---

## 사용 시점

- 코드 내 버그 위치를 특정할 때
- 어떤 커밋에서 버그가 도입됐는지 찾을 때
- 많은 양의 코드/변경사항 중 문제 지점을 찾을 때
- 문제가 재현 가능할 때

---

## 핵심 원리

**시간 복잡도**: O(log n)

100줄 코드에서 버그 찾기:
- 순차 탐색: 최대 100번 확인
- 이진 탐색: 최대 7번 확인 (log₂100 ≈ 7)

---

## 코드 디버깅

### Step 1: 범위 설정

문제가 있는 코드 범위를 설정합니다.

```
대상: src/auth/login.service.ts
범위: 1줄 ~ 200줄
```

### Step 2: 중간 지점 검증

중간 지점에 검증 포인트를 설정합니다.

```javascript
// 100줄 지점에 로그/breakpoint 추가
console.log('=== CHECKPOINT 100 ===', { user, token });
```

### Step 3: 정상/비정상 판단

중간 지점에서 상태가 정상인지 확인합니다.

```
100줄 지점: 정상 (user 데이터 있음)
→ 문제는 100줄 이후에 있음
```

### Step 4: 범위 축소

정상이면 후반부, 비정상이면 전반부로 범위를 좁힙니다.

```
기존 범위: 1-200
판단: 100줄 정상
새 범위: 100-200 (후반부)
```

### Step 5: 반복

문제 위치를 찾을 때까지 반복합니다.

```
Round 1: 1-200줄, 중간=100줄 → 정상 → 100-200
Round 2: 100-200줄, 중간=150줄 → 비정상 → 100-150
Round 3: 100-150줄, 중간=125줄 → 비정상 → 100-125
Round 4: 100-125줄, 중간=112줄 → 정상 → 112-125
Round 5: 112-125줄, 중간=118줄 → 비정상 → 112-118
Round 6: 112-118줄, 중간=115줄 → 정상 → 115-118
Round 7: 115-118줄 직접 확인 → 117줄에서 버그 발견!
```

## Git Bisect

Git에는 이 기법이 내장되어 있습니다.

### 사용법

```bash
# bisect 시작
git bisect start

# 현재 커밋이 문제 있음
git bisect bad

# 이 커밋은 정상이었음
git bisect good abc123

# Git이 자동으로 중간 커밋 체크아웃
# 테스트 후 good/bad 표시
git bisect good  # 또는 git bisect bad

# 반복...

# 문제 커밋 발견 후 종료
git bisect reset
```

### 자동화

```bash
# 테스트 스크립트로 자동화
git bisect run npm test
```

## 팁

### 1. 검증 포인트 선택

```javascript
// 좋은 검증 포인트: 핵심 데이터 상태
console.log('CHECKPOINT:', {
  user: !!user,
  token: !!token,
  isValid: user?.isValid
});

// 나쁜 검증 포인트: 너무 많은 정보
console.log('CHECKPOINT:', user, token, config, ...);
```

### 2. 재현 가능한 테스트

```bash
# 일관된 테스트 조건
NODE_ENV=test npm run test:login
```

### 3. 변경 최소화

각 라운드에서 하나의 검증 포인트만 추가/이동
