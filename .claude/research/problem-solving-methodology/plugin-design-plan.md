# 문제 해결 플러그인 설계 계획

## 개요

### 플러그인 목적
소프트웨어 개발 중 발생하는 문제(버그, 에러, 장애)를 **체계적으로 분석하고 해결**하는 프로세스를 자동화합니다.

### 핵심 가치
1. **체계적 접근**: 임의적 디버깅 대신 검증된 방법론 적용
2. **근본 원인 추적**: 증상 해결이 아닌 근본 원인 해결
3. **지식 축적**: 해결 사례를 기록하여 재발 방지 및 학습

---

## 플러그인 구조

### 1. 명령어 (Commands)

| 명령어 | 옵션 | 설명 |
|--------|------|------|
| `/solve [문제]` | - | 문제 해결 프로세스 시작 |
| `/solve --5whys` | - | 5 Whys 기법으로 원인 분석 |
| `/solve --rca` | - | Root Cause Analysis 실행 |
| `/solve --hypothesis` | - | 가설 기반 접근 |
| `/solve-log` | - | 진행 중인 문제 해결 로그 확인 |
| `/solve-history` | - | 과거 해결 사례 검색 |
| `/solve-report` | - | 문제 해결 보고서 생성 |

### 2. 스킬 (Skills)

```
.claude/skills/problem-solving/
├── SKILL.md                    # 스킬 정의
├── methods/
│   ├── five-whys.md           # 5 Whys 가이드
│   ├── rca.md                 # RCA 가이드
│   ├── hypothesis.md          # 가설 기반 접근 가이드
│   ├── binary-search.md       # Binary Search 디버깅
│   └── fishbone.md            # Fishbone 다이어그램
└── templates/
    ├── problem-report.md      # 문제 보고서 템플릿
    └── solution-report.md     # 해결 보고서 템플릿
```

### 3. 자동 활성화 조건

다음 키워드 감지 시 자동 활성화:
- "에러", "버그", "문제", "오류"
- "안 돼", "안되", "작동 안함"
- "해결", "디버깅", "디버그"
- "왜 이런지", "원인", "이유"

### 4. 저장 구조

```
.claude/problem-solving/
├── active/                     # 진행 중인 문제 해결
│   └── {problem-id}/
│       ├── problem.md          # 문제 정의
│       ├── analysis.md         # 원인 분석
│       ├── hypotheses.md       # 가설 목록
│       ├── experiments.md      # 실험 기록
│       └── solution.md         # 해결책
│
├── resolved/                   # 해결된 문제 아카이브
│   └── {problem-id}/
│       └── report.md           # 최종 보고서
│
└── knowledge-base/             # 지식 베이스
    ├── patterns.json           # 문제 패턴
    └── solutions.json          # 해결책 인덱스
```

## 상세 설계

### Phase 1: 문제 정의 (Define)

**입력**: 사용자가 문제 설명 제공

**출력**: 구조화된 문제 정의서

```markdown
## 문제 정의서

### 기본 정보
- **문제 ID**: PROB-001
- **보고 일시**: 2025-12-30 10:00
- **보고자**: 사용자

### 증상 (Symptom)
- **무엇이**: API 호출 실패
- **언제**: 로그인 시도 시
- **어디서**: /api/auth/login 엔드포인트
- **얼마나**: 모든 요청 (100%)

### 재현 조건
1. 로그인 페이지 접속
2. 이메일/비밀번호 입력
3. 로그인 버튼 클릭
4. 500 에러 발생

### 에러 정보
- **에러 메시지**: "Internal Server Error"
- **에러 코드**: 500
- **스택 트레이스**: [첨부]

### 영향 범위
- **심각도**: Critical
- **영향 사용자**: 전체
```

**Claude 동작**:
```
[SOLVE] 문제 정의 시작
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

문제를 이해하기 위해 몇 가지 질문이 있습니다:

Q1. 정확히 어떤 증상이 발생하나요?
Q2. 언제부터 발생했나요?
Q3. 에러 메시지나 로그가 있나요?
Q4. 최근 변경사항이 있었나요?

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

### Phase 2: 정보 수집 (Gather)

**자동 수집 항목**:
- Git 로그 (최근 커밋)
- 에러 로그 (있는 경우)
- 환경 정보 (Node 버전, 의존성 등)
- 관련 파일 목록

**출력**:
```markdown
## 수집된 정보

### Git 변경 이력 (최근 5개)
| 커밋 | 작성자 | 메시지 | 날짜 |
|------|--------|--------|------|
| abc123 | dev | feat: 로그인 로직 수정 | 1시간 전 |
| def456 | dev | fix: 타입 수정 | 2시간 전 |

### 관련 파일
- src/auth/login.ts (최근 수정)
- src/services/auth.service.ts

### 환경 정보
- Node.js: 18.17.0
- TypeScript: 5.0.0
```

### Phase 3: 원인 분석 (Analyze)

#### 3.1 5 Whys 분석

```
[SOLVE] 5 Whys 분석
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Why 1: 왜 500 에러가 발생하나요?
→ DB 쿼리에서 예외 발생

Why 2: 왜 DB 쿼리에서 예외가 발생하나요?
→ 사용자 테이블에 컬럼이 없음

→ 마이그레이션이 실행되지 않음

Why 4: 왜 마이그레이션이 실행되지 않았나요?
→ 배포 스크립트에서 누락됨

Why 5: 왜 배포 스크립트에서 누락됐나요?
→ CI/CD 파이프라인 변경 시 마이그레이션 단계 삭제됨

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

### 패턴 자동 학습

해결된 문제는 자동으로 패턴화:

```json
{
  "patterns": [
    {
      "id": "PAT-001",
      "symptom": "500 에러 + DB 관련",
      "keywords": ["500", "database", "query", "column"],
      "likely_causes": [
        "마이그레이션 누락",
        "DB 연결 문제",
        "쿼리 문법 오류"
      ],
      "solutions": ["PROB-001"]
    }
  ]
}
```
