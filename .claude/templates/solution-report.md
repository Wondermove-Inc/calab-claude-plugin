# 해결 보고서 템플릿

## 사용 목적

이 템플릿은 `/solve-report` 명령어에서 최종 문제 해결 보고서를 생성하기 위해 사용됩니다.
Blameless Postmortem 원칙에 따라 비난 없이 시스템 개선에 집중합니다.

---

## Blameless Postmortem 원칙

### 핵심 원칙

| 원칙 | 설명 | 예시 |
|------|------|------|
| **비난 없음** | 개인이 아닌 시스템에 집중 | "A가 실수했다" ❌ → "검증 프로세스가 없었다" ✅ |
| **학습 중심** | 처벌이 아닌 개선에 집중 | 징계 ❌ → 프로세스 개선 ✅ |
| **투명성** | 모든 정보 공개 | 일부 숨김 ❌ → 전체 공유 ✅ |
| **행동 지향** | 구체적 액션 아이템 | "주의하겠다" ❌ → "테스트 추가" ✅ |

### Blameless 작성 예시

**나쁜 예시 (Blame):**
```markdown
## 원인
개발자 A가 코드 리뷰 없이 배포하여 발생
```

**좋은 예시 (Blameless):**
```markdown
## 원인
코드 리뷰 없이 배포가 가능한 프로세스 취약점으로 인해 검증되지 않은 변경이 프로덕션에 반영됨

## 재발 방지
- PR 머지 시 최소 1인 리뷰 필수 (GitHub 브랜치 보호 규칙)
- CI 파이프라인에 자동화 테스트 추가
```

## 보고서 품질 체크리스트

### 필수 항목

- [ ] 문제 ID와 제목이 명확함
- [ ] 타임라인이 정확함
- [ ] 근본 원인이 증거와 함께 기술됨
- [ ] 해결책이 구체적으로 기술됨
- [ ] 재발 방지 액션이 담당자와 기한 포함
- [ ] 검증 결과가 기록됨

### 품질 확인

- [ ] 비난 없이 시스템 중심으로 작성됨
- [ ] 교훈과 개선점이 명확함
- [ ] 액션 아이템이 추적 가능함
- [ ] 관련 링크가 모두 유효함

## 금지 사항

### 해결 보고서 작성 시 하지 말아야 할 것

1. **비난**
   - 특정 개인을 지목하는 표현 금지
   - "실수", "부주의" 등 개인 책임 표현 금지
   - 시스템/프로세스 개선에 집중

2. **내용**
   - 증거 없는 추측 기술 금지
   - 해결책 없이 원인만 기술 금지
   - 액션 아이템 없이 마무리 금지

3. **형식**
   - 담당자/기한 없는 액션 아이템 금지
   - 검증 없이 "해결됨" 표시 금지
   - 후속 추적 계획 없이 종료 금지
