# /qa-report - QA 보고서 생성

## 설명

QA 테스트 결과를 **종합 보고서**로 생성합니다.
테스트 통과율, 버그 목록, 스크린샷, 권장 사항을 포함합니다.

---

## 사용법

```bash
/qa-report                  # 전체 보고서 생성
/qa-report --summary        # 요약 보고서만
/qa-report --full           # 상세 보고서 (모든 스크린샷 포함)
/qa-report --bugs           # 버그 보고서만
/qa-report --export pdf     # PDF 형식으로 내보내기
```

---

## 보고서 생성 프로세스

### Step 1: 데이터 수집

**수집 파일:**

| 파일 | 내용 |
|------|------|
| `.claude-state/qa/qa-status.json` | 전체 진행 상태 |
| `.claude-state/qa/test-results.json` | 테스트 결과 |
| `.claude-state/qa/bugs.json` | 발견된 버그 |
| `.claude-state/qa/screenshots/` | 스크린샷 |

### Step 2: 통계 계산

```markdown
## 통계

| 항목 | 수치 | 비율 |
|------|------|------|
| 총 테스트 | 30 | 100% |
| 통과 | 27 | 90% |
| 실패 | 2 | 7% |
| 블록됨 | 1 | 3% |

### 우선순위별
| 우선순위 | 통과 | 실패 | 통과율 |
|----------|------|------|--------|
| P0 | 8/8 | 0 | 100% |
| P1 | 11/12 | 1 | 92% |
| P2 | 8/10 | 2 | 80% |
```

### Step 3: 버그 분석

```markdown
## 버그 요약

| 심각도 | 개수 | 상태 |
|--------|------|------|
| Critical | 0 | - |
| Major | 1 | Open |
| Minor | 2 | 1 Open, 1 Fixed |
| Trivial | 1 | Open |
```

### Step 4: 보고서 생성

**생성 파일:**

```
.claude/docs/active/{feature-name}/qa/
├── QA_REPORT.md           # 메인 보고서
├── BUG_REPORT.md          # 버그 상세 보고서
└── TEST_RESULTS.md        # 테스트 결과 상세
```

## 6. 권장 사항

### 6.1 필수 조치 (릴리스 전)

1. **BUG-001 해결**: 이메일 인증 API 오류 수정
2. **TC-028 테스트 완료**: 결제 시스템 연동 후 테스트

### 6.2 권장 조치

1. **BUG-002**: 검색 필터 반응형 스타일 개선
2. **성능 개선**: 상품 목록 로딩 시간 3초 → 1초

### 6.3 다음 테스트 사이클

1. 회귀 테스트: 버그 수정 후 관련 기능 재테스트
2. 추가 테스트: 관리자 페이지 QA 별도 진행

## 옵션 설명

| 옵션 | 설명 |
|------|------|
| `--summary` | 요약 보고서만 (1페이지) |
| `--full` | 전체 보고서 (스크린샷 모두 포함) |
| `--bugs` | 버그 보고서만 |
| `--export pdf` | PDF 형식으로 내보내기 |
| `--format html` | HTML 형식으로 생성 |
