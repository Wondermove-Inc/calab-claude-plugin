# 5 Whys 기법

## 개요

**5 Whys**는 Toyota Production System에서 개발된 근본 원인 분석 기법입니다.
반복적으로 "왜?"를 질문하여 표면적 원인을 넘어 근본 원인을 찾아냅니다.

---

## 사용 시점

- 원인이 명확하지 않을 때
- 표면적 해결이 반복될 때
- 빠르게 근본 원인을 찾고 싶을 때
- 복잡한 도구 없이 분석할 때

---

## 프로세스

### Step 1: 문제 명시

문제를 구체적이고 명확하게 정의합니다.

```
❌ 나쁜 예: "서버가 느려요"
✅ 좋은 예: "로그인 API 응답 시간이 5초 이상 소요됨"
```

### Step 2: 첫 번째 "왜?"

문제의 직접적인 원인을 찾습니다.

```
문제: 로그인 API 응답 시간이 5초 이상
Why 1: 왜 응답이 느린가?
→ DB 쿼리가 4.5초 소요
```

### Step 3: 반복 질문

이전 답변에 대해 계속 "왜?"를 질문합니다.

```
Why 2: 왜 DB 쿼리가 느린가?
→ users 테이블 풀스캔 발생

Why 3: 왜 풀스캔이 발생하는가?
→ email 컬럼에 인덱스 없음

Why 4: 왜 인덱스가 없는가?
→ 스키마 설계 시 누락됨

Why 5: 왜 누락됐는가?
→ 쿼리 패턴 분석 없이 설계됨
```

### Step 4: 근본 원인 확정

더 이상 "왜?"가 의미없을 때 = 근본 원인

```
근본 원인: 쿼리 패턴 분석 프로세스 부재
```

### Step 5: 해결책 도출

근본 원인에 대한 해결책 수립

```
즉시 조치: email 컬럼에 인덱스 추가
근본 해결: DB 설계 시 쿼리 패턴 분석 체크리스트 추가
```

## 예시

### 예시 1: 배포 실패

```
문제: 프로덕션 배포 실패

Why 1: 왜 배포가 실패했나?
→ 테스트가 실패함

Why 2: 왜 테스트가 실패했나?
→ API 스펙 변경됨

Why 3: 왜 스펙이 변경됐나?
→ 새 필드 추가됨

Why 4: 왜 테스트가 업데이트 안됐나?
→ PR에서 테스트 변경 누락

Why 5: 왜 누락됐나?
→ 코드 리뷰 체크리스트에 테스트 확인 항목 없음

근본 원인: 코드 리뷰 체크리스트 미흡
해결책: "관련 테스트 업데이트 확인" 항목 추가
```

### 예시 2: 메모리 누수

```
문제: 서버 메모리 지속 증가

Why 1: 왜 메모리가 증가하나?
→ 객체가 GC되지 않음

Why 2: 왜 GC 안되나?
→ 이벤트 리스너가 참조 유지

Why 3: 왜 리스너가 유지되나?
→ removeEventListener 호출 안됨

Why 4: 왜 호출 안되나?
→ 컴포넌트 언마운트 시 cleanup 없음

Why 5: 왜 cleanup이 없나?
→ 코드 템플릿에 cleanup 패턴 없음

근본 원인: 코드 템플릿/보일러플레이트 미흡
해결책: useEffect cleanup 패턴 포함한 템플릿 제공
```

## 주의사항

### 1. 사실 기반 답변

```
❌ 추측: "아마 설정이 잘못됐을 거예요"
✅ 사실: "로그 확인 결과 설정 파일에서 에러 발생"
```

### 2. 5번이 정답 아님

상황에 따라 3~7회 유동적으로 조정

```
간단한 문제: 3 Whys로 충분
복잡한 문제: 7 Whys까지 필요할 수 있음
```

### 3. 다중 원인 분기

하나의 Why에 여러 답변이 있을 수 있음

```
Why 2: 왜 에러가 발생했나?
→ 원인 A: 입력값 검증 실패
→ 원인 B: DB 연결 끊김

각 원인별로 별도 분석 진행
```

### 4. 비난 금지

사람이 아닌 프로세스에 집중

```
❌ 나쁜 예: "개발자가 실수해서"
✅ 좋은 예: "코드 리뷰 프로세스에서 검증 누락"
```

## 관련 방법론

- **RCA**: 더 체계적인 분석이 필요할 때
- **Fishbone**: 다중 원인 시각화가 필요할 때
- **가설 기반**: 검증이 필요할 때
